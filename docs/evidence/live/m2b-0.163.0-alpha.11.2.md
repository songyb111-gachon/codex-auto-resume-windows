# M2b: observed pass on codex-cli 0.163.0-alpha.11.2 (2026-10-23)

This is an additional live observation, not a replacement for the original
canonical measurement record on 0.163.0-alpha.10.2. It is deliberately
content-free: no private goal objective, prompt, thread ID, account data,
repository, or path is included.

The existing Codex desktop app held a conversation with a goal paused by a
usage limit. A single native thread/goal/set activation followed by one
thread/queue/add returned an accepted queue ID. The same goal read back as
active. The queue item was consumed once, and a new turn appeared as
inProgress. That turn later completed. The goal remained active and
continued into a later turn, which eventually hit the next usage limit.
No manual second send was made for that recovery.

This confirms the particular M2b behavior required by the Goal continuation
channel on this exact engine version: activate the existing goal first,
then queue one continuation in a conversation held by the desktop app, without
losing the goal. It does not certify future versions or guarantee that a
different queue transport (codex queue) works.
